# 0001 — Backend language: Go

Status: ACCEPTED · 2026-07-16

## Context

New service integrating the Reap card issuing API with the Vultisig apps. Workload: webhook ingestion with signature verification, a small REST API, a PostgreSQL ledger, push fan-out, background reconciliation, and MPC signature verification (secp256k1 + ed25519) at enrollment. It must also call VultiServer (Go) for Fast-Vault co-signing.

## Decision

Go (1.26). Standard module layout, `internal/` packages, stdlib-first.

## Consequences

- Matches the existing Vultisig server-side stack (VultiServer, verifier, marketplace) — shared idioms, shared reviewers, Go-to-Go integration with the co-signer.
- Mature primitives for the security-sensitive parts: `crypto/hmac`, `crypto/subtle` constant-time compare, well-audited secp256k1/ed25519 libraries.
- Small dependency surface (module checksums, no post-install scripts) for a service that will be security-reviewed.
- Rejected: TypeScript (splits from the Go signing infra; larger supply-chain surface for a money-path service). Rust (team velocity cost not justified — the service is I/O orchestration, not compute).
